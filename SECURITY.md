# Security policy

## Reporting a vulnerability
Email the address in `/.well-known/security.txt` (set via `SECURITY_CONTACT`). Please do not open public issues for vulnerabilities.

## Design
- Static site: no database, no server-side session, no user accounts. Very small attack surface.
- Strict `Content-Security-Policy` (`script-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`), HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP. Generated by `scripts/postbuild.mjs` into `dist/_headers`.
- Zero third-party scripts, fonts or trackers by default. Everything is self-hosted.
- The only dynamic endpoint is `functions/api/quote.js` (Cloudflare Pages Function): same-origin only, JSON only, 8 KB cap, server-side validation and sanitising, plain-text email, per-IP throttle, honeypot. Secrets are environment variables, never shipped to the browser.
- `npm audit` runs in CI; Dependabot opens weekly update PRs. Production dependencies are pinned by `package-lock.json`.

## Operator checklist
- Turn on a Cloudflare WAF rate-limiting rule for `/api/quote` (e.g. 5 requests / 10 min / IP).
- Enable 2FA on GitHub, Cloudflare, your domain registrar and email. Account takeover is the realistic threat to a site like this.
- Keep `Expires` in `security.txt` current (it is regenerated on every build).
- If you enable AdSense, the CSP is relaxed for Google (see `docs/ADSENSE.md`); review it.
